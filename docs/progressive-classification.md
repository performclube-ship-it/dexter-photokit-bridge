# DEXTER — progressive, local-only Vision review coordinator (23 Nov 2026)

This is a standalone, pure JavaScript **helper for the original DEXTER PhotoKit bridge**, not a new application. It coordinates the previously merged Swift `classifyPilotAssets` method. It is not installed in Floot or TestFlight.

`classifyLocalPages({plugin, assetPages, expectedCount, onReviewBatch, batchSize, shouldStop, onProgress})` consumes an async iterable of **1–250 locally saved PHAsset identifiers per page**, with exactly the user-selected `expectedCount` (not necessarily the whole library). It sends **at most ten** IDs per native Vision request; it never passes pixels to JavaScript or calls PhotoKit mutations. Full Photos permission is required, and the caller must opt in to classification. IDs are unique within the whole invocation; extra, missing, malformed or swapped results abort rather than silently discard photos.

The helper invokes `onReviewBatch` only after validating all native results. The app must visibly queue/review ALL suggestions for the user and only return `{acknowledged:true}` after its local handling is complete. **Never store Vision labels on a server, log them or map them automatically to albums.** No album additions or deletions occur in this helper. `icloud` / `unavailable` produce a retry list of device-local ID/status pairs; `retry_pending` and `complete:false` are returned if any were encountered. `unsupported` counts separately. User-defined album names and explicit album/photo confirmation remain separate prerequisites.

On cancel before/during the native call, results not acknowledged are discarded without progress, and all IDs must be revisited on restart. On cancel during a durable `onReviewBatch`, previously acknowledged counts remain but the run stays `stopped/complete:false`. Keep a per-user, **local-only** de-duplicated status journal keyed by the device's PHAsset.localIdentifier. Do not persist session tokens or synchronize these IDs across iPhones. A new invocation re-enumerates the source from zero rather than trusting a stale offset.

**Synthetic validation only:** `node --test test/progressive-classification.test.mjs` covers 10,005 identifiers (1,001 native batches), iCloud requeue, invalid/swapped/short responses, missing/duplicate IDs, acknowledgements, cancellation and limited Photos permission. These tests **do not** measure device memory or Apple Vision accuracy. Swift already caps each invocation at ten images and disables iCloud network downloads; the application still needs device tests with a small non-sensitive library before growing usage. The latest original Floot Project ZIP remains necessary to integrate the native pod and safe review UI. The Floot daily action quota was still blocked before its documented reset at 09:00 UTC on 23 November, so no Floot build/publish actions were used.
